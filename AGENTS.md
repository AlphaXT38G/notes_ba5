# AGENTS.md

Guide for anyone working on this repository, human or AI agent (Claude Code reads it through
`CLAUDE.md`).

## What this repository is

LaTeX notes for the BA5 IN semester at EPFL, and nothing else: the subjects, their documents, and
two small files describing the site. `notes-engine` compiles every subject to PDF and generates
`dist/index.html`, an index page of all the PDFs. On every push to `main`, and every day at 04:00 UTC
(so the "New" badges expire), the GitHub Pages workflow (`.github/workflows/pages.yml`) runs the
build and publishes `dist/` at <https://alphaxt38g.github.io/notes_ba5/>.

**The website itself (page, search, screens, LaTeX styles, build code) is the notes engine**, in its own
repository, <https://github.com/AlphaXT38G/notes-engine> (its `AGENTS.md` explains it), shared by the notes of
every semester. This repository only configures it, and follows the engine's `main` in `requirements.txt`
and in the workflow, so it always builds with the latest engine (the daily 04:00 UTC run picks up engine
changes within a day; re-run the workflow to get them at once).

**When the semester ends, freeze the engine's version**: tag the engine's last commit (`vX.Y.Z`), then
replace `main` by that tag in `requirements.txt` and in both places of `pages.yml` (`uses:` and
`engine-ref:`). That tag is then the version this semester stopped at.

## Repository layout

```
requirements.txt      the engine's version (follows its main; a tag once frozen)
subjects.json         subjects: id, display name, exam rules, optional "weeks", "week_pdfs" and "color"
site.json             the site's settings: title, subtitle, short name, GitHub repo, kinds of documents
<subject>/            course.tex, cheatsheet.tex, week/NN.tex (chapters), extra PDFs...
<subject>/quiz/       optional: the course's quiz, one JSON file per chapter (see "Quizzes")
dist/                 build output (git-ignored): PDFs, previews, index.html, search.json
```

## Build and preview locally

```bash
pip install -r requirements.txt  # once: the engine
notes-engine                    # compile everything, then the index page
notes-engine compsec swent   # only some subjects (then the index page)
notes-engine --index-only    # only the index page, from the PDFs already in dist/
python -m http.server 8765 --directory dist   # then open http://localhost:8765/
```

- **Windows**: prefix the build with `PYTHONIOENCODING=utf-8`, or the console cannot print the symbols.
- **Optional tools**: `pdftoppm` and `pdftotext` (poppler) make the thumbnails and the text the search
  looks into; `node` checks the page's JavaScript. See the engine's `AGENTS.md`.
- **Never edit `dist/`**: it is regenerated by every build.
- Some documents do not compile today because of missing images (e.g.
  `respsoft/cheatsheet.tex`, `compsec/cheatsheet.tex`). That is expected until the images are added.
- Changes to the page or the build go to the engine's repository, with its own checks; try them here by
  installing it in editable mode: `pip install -e ../notes-engine`.

## Quizzes

A course with a `quiz/` folder gets a **Quiz** button on its card, right under the course notes.
It opens the quiz in the page, in the colours of the screen on show: the reader picks weeks,
chapters and kinds of exercise, then answers question by question. How quizzes work is
[quiz-engine](https://github.com/AlphaXT38G/quiz-engine)'s (its README and `AGENTS.md` list every
type and key; `example/quiz/week3.json` there has one of each); the engine builds them, and this
repository only writes the questions.

### Where the files go

```
swent/quiz/
  week1a.json         one file per chapter: its title, its week, its questions
  week1b.json         the week is the number in the file name (week1a -> 1), or "week": 3
  week2.json
  img/                pictures used by the questions (planets.png...), any name
```

Name the files like the chapters (`week1a.json` for `weeks/week1a.tex`, `01.json` for
`week/01.tex`) so the weeks line up with the notes. A file:

```json
{
  "title": "Requirements",
  "questions": [
    {"type": "scq", "question": "...", "options": ["...", "..."], "answer": 0, "explanation": "..."}
  ]
}
```

Every question has `type`, `question` and an optional `explanation` (shown after the answer).
Text can use `**bold**`, `*italic*`, `` `code` `` and `\n` for a new line; never HTML.

### One example of each kind

Single choice (`answer`: the index of the right option, from 0) and multiple answers (`answer`:
the list of right ones; options are shuffled unless `"shuffle": false`):

```json
{"type": "scq", "question": "Which document lists what the system must do?",
 "options": ["The requirements", "The test plan", "The changelog"], "answer": 0}

{"type": "mcq", "question": "Which are **non-functional** requirements?",
 "options": ["Response time", "Login", "Availability", "Search"], "answer": [0, 2]}
```

True or false:

```json
{"type": "tf", "question": "A user story is written from the user's point of view.", "answer": true}
```

Put in order (pictures from `quiz/img/`, or plain words), listed in the right order; the reader
gets them shuffled and drags them:

```json
{"type": "order", "question": "Order the phases of the waterfall model",
 "items": [{"img": "img/requirements.png", "label": "Requirements"}, "Design", "Implementation", "Testing"]}
```

A diagram, flowchart or organisation chart to complete (`flow`). Every box is a node, by id:
a text, or `{"text": ...}` / `{"blank": ...}` (a box to fill in: the answer, or a list of accepted
answers, compared ignoring case, accents and punctuation) with an optional `"shape"`: `box`
(default), `round` (start / end), `diamond` (a decision). `rows` places them top to bottom, each
row centred; `edges` are the arrows, `[from, to]` or `[from, to, "label"]`. An organisation chart:

```json
{"type": "flow", "question": "Complete the organisation chart of a start-up",
 "nodes": {
   "ceo": "CEO",
   "cto": {"blank": ["CTO", "Chief Technology Officer"]},
   "cfo": "CFO",
   "dev": "Developers",
   "qa":  {"blank": ["QA", "Testers", "Quality assurance"]}
 },
 "rows":  [["ceo"], ["cto", "cfo"], ["dev", "qa"]],
 "edges": [["ceo", "cto"], ["ceo", "cfo"], ["cto", "dev"], ["cto", "qa"]]}
```

A flowchart, with a decision and labelled arrows:

```json
{"type": "flow", "question": "Complete the flowchart: is **n** even?",
 "nodes": {
   "start": {"text": "Start", "shape": "round"},
   "test":  {"text": "n mod 2 = 0 ?", "shape": "diamond"},
   "even":  {"blank": ["even", "n is even"]},
   "odd":   {"blank": ["odd", "n is odd"]}
 },
 "rows":  [["start"], ["test"], ["even", "odd"]],
 "edges": [["start", "test"], ["test", "even", "yes"], ["test", "odd", "no"]]}
```

Draw a curve (`plot`): the formula (`x`, numbers, `+ - * / ^`, parentheses, `2x`, `pi`, `e`,
`sin cos tan exp ln log sqrt abs`), the ranges of the axes, and an optional `tolerance` (how far
the drawing may stray, as a share of the y range, 0.06 by default):

```json
{"type": "plot", "question": "Draw the curve of **y = x²**", "fn": "x^2", "x": [-3, 3], "y": [-1, 9]}
```

### Check it, see it

A mistake (a typo in a key, an answer out of range, a missing picture) is reported by the build
with the file and the question, and that quiz is left out of the site. Check before pushing, and
look at it in the page (quiz-engine is read from `../quiz-engine`, next to the engine):

```bash
python -m quiz_engine check swent/quiz        # from ../quiz-engine, or once: pip install -e ../quiz-engine
notes-engine --index-only                     # builds the quizzes too
python -m http.server 8765 --directory dist   # then http://localhost:8765/#quiz/swent
```

Add `?screen=halloween` (or `christmas`, `evening`, `sakura`...) before the `#` to see it on a
screen: `http://localhost:8765/?screen=halloween#quiz/swent`.

## Workflow

- **Branch** from an up-to-date `main` (`feat/...`, `fix/...`, `refactor/...`), open a PR.
- **Commits**: [Conventional Commits](https://www.conventionalcommits.org/) in English, one
  commit per change, `type(scope): summary`. Types used here: `feat`, `fix`, `style`, `perf`,
  `refactor`, `docs`, `build`, `ci`, `chore`. Scopes: `engine` (the page and the build), `build`,
  or a subject and document (`compsec-week05`, `respsoft-cheatsheet`, `swent-quiz`).
- **Before committing**: `notes-engine` (the subjects you touched) and open the PDFs; for a page
  change, see the engine's `AGENTS.md`.
- Keep `README.md` (for readers) and this file (for contributors) up to date with what changes.

## LaTeX notes

- A course can be split into chapters `\input` by `course.tex`: compsec's are `week/01.tex`,
  `02.tex`... (one lecture per file, no `\documentclass`), swent's `weeks/week1a.tex`,
  `week1b.tex`... (several parts per week; name new ones `weekN` + optional letter). Unless the
  subject says `"week_pdfs": false` in `subjects.json` (compsec: it would only repeat
  `course.pdf`), the engine's `latex.py` also builds one PDF per week from generated `_weekNN.tex`
  files (git-ignored: the course preamble plus that week's parts), published as `week/NN.pdf`.
- The "weekly notes" section of a card lists the PDFs of a `week/` or `notes/` folder named `NN`
  or `weekNN` (`weekly()` in the engine's `config.py`), with a progress bar (`"weeks"` in
  `subjects.json` sets its length, 14 by default). compsec's weekly notes are the standalone
  documents of `compsec/notes/` (`weekNN.tex`, each with its own `\documentclass`).
- `compsec/course2.tex` is the explained copy of the compsec course: its chapters are in
  `compsec/course2/` (`00.tex` preliminaries, then a copy of each `week/NN.tex`), completed from
  the slides, with "Explained to a goat" boxes, an exam-ready recap per chapter (saying how it
  builds on the earlier ones) and, in `04.tex`, a `forest` tree of every access control seen.
  `course.tex` and `week/` stay as they are. It shows on the card as "Course notes, explained"
  (`kinds` in `site.json`), among the other documents.
- `elec/course.tex` is the electronics course, explained, in French, written from the commented
  slides (C00 to C07): one chapter per lecture in `elec/course/` (`00.tex` ... `07.tex`) and a
  general exam recap (`08.tex`: formula sheet, step-by-step methods, pitfalls). Like compsec's,
  each chapter has "Expliqué à une chèvre" boxes and ends with an exam recap saying how it builds
  on the others. Screenshots of the slides are in `elec/images/course/` (`cNN-PP.png`: lecture
  NN, page PP of the commented PDF), shown with the `\slide[width]{cNN-PP}{caption}` command of
  `course.tex`. Worked numbers that are not in the slides are labelled as such.
- `comecma/course.tex` (MSE 234, Comportement mécanique des matériaux) follows the same model, in
  French: one chapter per chapter of the slides in `comecma/course/` (`01.tex` essais mécaniques,
  `02.tex` céramiques, `03.tex` Al, Cu et alliages, `04.tex` fer et aciers) and a general exam
  recap (`05.tex`: the official list of formulas to know by heart, methods, pitfalls); add the
  polymers and composites as new chapters before it. Screenshots are in `comecma/images/course/`
  (`cNN-PP.png`, `c03a`/`c03b`/`c03c` for the three PDFs of chapter 3). Its weekly notes
  (`comecma/week/weekNN.tex`, standalone two-column documents, each section ending with a goat box
  and the document with a "Récap pour l'examen") reuse those screenshots; their week numbers follow
  the lecture each part was taught in (no lecture in weeks 03 and 07).
- Courses and cheat sheets load `\usepackage{course}` / `\usepackage{cheatsheet}`, the engine's styles
  (the engine's `notes_engine/shared/`; layout, boxes, footer with the repository link of `site.json`). No path is needed:
  the build sets `TEXINPUTS`. Change the look of all of them there.
- A PDF without a matching `.tex` (e.g. `respsoft/cheatsheets/*.pdf`) is copied as is.
