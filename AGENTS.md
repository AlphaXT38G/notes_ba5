# AGENTS.md

Guide for anyone working on this repository, human or AI agent (Claude Code reads it through
`CLAUDE.md`).

## What this repository is

LaTeX notes for the BA5 IN semester at EPFL, and nothing else: the subjects, their documents, and
two small files describing the site. `notes-engine` compiles every subject to PDF and generates
`dist/index.html`, an index page of all the PDFs. On every push to `main`, and every day at 04:00 UTC
(so the "New" badges expire), the GitHub Pages workflow (`.github/workflows/pages.yml`) runs the
build and publishes `dist/` at <https://alphaxt38g.github.io/notes_ba5/>.

**The website itself (page, search, screens, LaTeX styles, build code) is the notes engine**, in its own
repository, <https://github.com/AlphaXT38G/notes-engine> (its `AGENTS.md` explains it), shared by the notes of
every semester. This repository only configures it, and pins a tag of it in `requirements.txt` and in
the workflow: to take a new version, change the tag in both.

## Repository layout

```
requirements.txt      pins the engine's version
subjects.json         subjects: id, display name, exam rules, optional "weeks", "week_pdfs" and "color"
site.json             the site's settings: title, subtitle, short name, GitHub repo, kinds of documents
<subject>/            course.tex, cheatsheet.tex, week/NN.tex (chapters), extra PDFs...
dist/                 build output (git-ignored): PDFs, previews, index.html, search.json
```

## Build and preview locally

```bash
pip install -r requirements.txt  # once: the engine
notes-engine                    # compile everything, then the index page
notes-engine compsec swent   # only some subjects (then the index page)
notes-engine --index-only    # only the index page, from the PDFs already in dist/
python -m http.server 8765 --directory dist   # then open http://localhost:8765/
```

- **Windows**: prefix the build with `PYTHONIOENCODING=utf-8`, or the console cannot print the symbols.
- **Optional tools**: `pdftoppm` and `pdftotext` (poppler) make the thumbnails and the text the search
  looks into; `node` checks the page's JavaScript. See the engine's `AGENTS.md`.
- **Never edit `dist/`**: it is regenerated by every build.
- Some documents do not compile today because of missing images (e.g. `elec/course.tex`,
  `respsoft/cheatsheet.tex`, `compsec/cheatsheet.tex`). That is expected until the images are added.
- Changes to the page or the build go to the engine's repository, with its own checks; try them here by
  installing it in editable mode: `pip install -e ../notes-engine`.

## Workflow

- **Branch** from an up-to-date `main` (`feat/...`, `fix/...`, `refactor/...`), open a PR.
- **Commits**: [Conventional Commits](https://www.conventionalcommits.org/) in English, one
  commit per change, `type(scope): summary`. Types used here: `feat`, `fix`, `style`, `perf`,
  `refactor`, `docs`, `build`, `ci`, `chore`. Scopes: `engine` (the page and the build), `build`,
  or a subject and document (`compsec-week05`, `respsoft-cheatsheet`).
- **Before committing**: `notes-engine` (the subjects you touched) and open the PDFs; for a page
  change, see the engine's `AGENTS.md`.
- Keep `README.md` (for readers) and this file (for contributors) up to date with what changes.

## LaTeX notes

- A course can be split into chapters `\input` by `course.tex`: compsec's are `week/01.tex`,
  `02.tex`... (one lecture per file, no `\documentclass`), swent's `weeks/week1a.tex`,
  `week1b.tex`... (several parts per week; name new ones `weekN` + optional letter). Unless the
  subject says `"week_pdfs": false` in `subjects.json` (compsec: it would only repeat
  `course.pdf`), the engine's `latex.py` also builds one PDF per week from generated `_weekNN.tex`
  files (git-ignored: the course preamble plus that week's parts), published as `week/NN.pdf`.
- The "weekly notes" section of a card lists the PDFs of a `week/` or `notes/` folder named `NN`
  or `weekNN` (`weekly()` in the engine's `config.py`), with a progress bar (`"weeks"` in
  `subjects.json` sets its length, 14 by default). compsec's weekly notes are the standalone
  documents of `compsec/notes/` (`weekNN.tex`, each with its own `\documentclass`).
- `compsec/course2.tex` is the explained copy of the compsec course: its chapters are in
  `compsec/course2/` (`00.tex` preliminaries, then a copy of each `week/NN.tex`), completed from
  the slides, with "Explained to a goat" boxes, an exam-ready recap per chapter (saying how it
  builds on the earlier ones) and, in `04.tex`, a `forest` tree of every access control seen.
  `course.tex` and `week/` stay as they are. It shows on the card as "Course notes, explained"
  (`kinds` in `site.json`), among the other documents.
- Courses and cheat sheets load `\usepackage{course}` / `\usepackage{cheatsheet}`, the engine's styles
  (the engine's `notes_engine/shared/`; layout, boxes, footer with the repository link of `site.json`). No path is needed:
  the build sets `TEXINPUTS`. Change the look of all of them there.
- A PDF without a matching `.tex` (e.g. `respsoft/cheatsheets/*.pdf`) is copied as is.
